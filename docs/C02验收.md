# C02 按键与 LED 验收

## 本阶段行为

- PC8/PC9 使用已有 KEY1/KEY2 宏和上拉输入，低电平按下；不改引脚或 CubeMX GPIO 配置。
- 主循环目标每 5 ms 扫描一次；按下和释放都要求采样电平连续稳定 20 ms。
- 每次确认按下只产生一个事件，保持按住不重复触发；释放消抖完成后才允许下一次按下。
- 两键独立消抖，可同时产生事件；上电已经按住的键不触发，需先释放再按。
- K1 通过串口输出翻页请求，OLED 尚未接入，不提前实现 UI。
- K2 切换本地测试报警标志并控制 LED，不触发网络、语音或跌倒算法。

## LED 模式

| 模式 | 电平/节奏 | 含义 |
|---|---|---|
| OFF | 高电平，灭 | 未初始化完成或验收预览 |
| NORMAL | 每 500 ms 翻转，完整周期约 1 s | 正常，1 Hz |
| ALARM | 每 100 ms 翻转，完整周期约 200 ms | 报警，5 Hz |
| OFFLINE | 低电平，常亮 | 网络未连接 |

开机从 app_init 起依次预览：灭约 1 s → 慢闪约 2 s → 快闪约 1 s → 离线常亮。预览只用于 C02 上板验收，进入后续业务阶段时撤下；其中的快闪不设置测试报警标志。

按下 K2 会立即结束预览，并切换测试报警；报警优先显示快闪，取消后回离线常亮。网络业务尚未接入，不能将常亮解读为故障或已联网。

## 构建与固件

新增 BSP/bsp_key.c/h，扩展 BSP/bsp_led.c/h 和 App/app_main.c；根 CMakeLists.txt 添加按键源码。Core/Src/main.c 只在 USER CODE 块更新 C02 日志，保留已验收的 RTC/TIM2 诊断。

使用 STM32 GNU Arm 14.3.1 + CMake 4.4.0 + Ninja，Debug 编译链接通过，无编译警告。固件为 build/Debug/fallguard.elf。工具已加入 PATH 时：

    cmake --preset Debug
    cmake --build --preset Debug

C01 已由用户上板确认通过：HCLK 配置 72 MHz、LSE_READY=1，RTC 连续走秒，TIM2 周期计数及 LED 亮灭正常。本阶段沿用这些初始化。

## 上板验收

烧录新 ELF，用 USART1 串口助手 115200、8N1、无流控观察，打开串口后复位。

1. 不按键观察开机预览四种模式；约 4 s 后 LED 应持续亮。启动标题应为 fallguard C02。
2. K1 短按一次应只输出一条：

       [C02] K1: page next

   保持按住 2 s 不应连续输出；释放后再按，才增加一条。
3. K2 第一次短按应只输出：

       [C02] K2: test alarm ON

   LED 应持续快闪；长按不重复切换。释放后第二次短按输出 OFF，LED 回常亮。这里的 OFF 表示测试报警取消，不表示 LED 熄灭。
4. 连续正常按下/释放 K1 十次，应得到十条 K1 日志；按下和释放各保持约 100 ms，避免把快于消抖时间的动作当成漏报。
5. 两键同时按住，应各输出一次；保持期间均不重复。一键保持按住时，另一键仍可独立产生新事件。
6. 分别按住 K1/K2 再复位，保持一会儿：不应产生该键的按下事件。释放不会输出事件，下一次按下才触发。
7. 全程 RTC/TIM2 每秒诊断应继续输出。开机预览、闪灯和消抖均未使用 HAL_Delay。

上述是待执行的硬件验收步骤，不是已获得的实测结果。机械按键抖动是否得到充分抑制、两键接线及实际 LED 节奏需用户上板确认。通过后再进入 C03。
