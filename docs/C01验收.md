# C01 工程骨架验收

本阶段接入 App/BSP，使用 tick 轮询闪灯，提供 USART1 启动日志和时钟诊断。按键、GPS/IMU、语音及网络业务暂不接入。

## 文件

- App/app_main.c/h：app_init、app_run，LED 每 500 ms 翻转。
- BSP/bsp_led.c/h：使用 LED_Pin/LED_GPIO_Port，初始化为高电平熄灭。
- Core/Src/main.c：仅修改 USER CODE 块，接入 App、printf、TIM2 启动和 C01 时钟诊断。
- 根 CMakeLists.txt：显式添加 App/BSP 源文件及 include 路径。

C01 的 RTC/TIM2 诊断位于 Core 的 USER CODE 块，App 只直接调用允许的 HAL_GetTick，不访问外设句柄。后续 UI/业务的 RTC 访问仍通过 BSP 接入。

## 编译

已使用本机 STM32 GNU Arm 14.3.1、CMake 4.4.0、Ninja 完成 Debug 全量编译，32 个构建步骤通过，无编译警告。

工具已加入当前终端 PATH 时，在根目录执行：

    cmake --preset Debug
    cmake --build --preset Debug

固件：build/Debug/fallguard.elf。

## 上板步骤与通过标准

1. 接 ST-Link，使用现有下载工具烧录 ELF，打开 USART1 串口助手：115200、8N1、无流控。USB-TTL RX 接 PA9，GND 共地；只观察日志不必接 USB-TTL TX。串口助手打开后复位板子，以便看到启动日志。
2. 应看到启动信息：

       === fallguard C01 ===
       [C01] HCLK=72000000 Hz LSE_READY=1
       [C01] TIM2 started, LED toggle=500 ms, RTC time uncalibrated

3. PA8 LED 应每 500 ms 翻转一次：高电平灭、低电平亮，一个完整亮灭周期约 1 s。没有使用 HAL_Delay，主循环持续运行。
4. 每秒应看到类似：

       [C01] tick=1000 rtc=00:00:01 tim2=16960
       [C01] tick=2000 rtc=00:00:02 tim2=33920

   tick、tim2 的具体数值和 RTC 的首条读数可因启动/串口耗时不同；验收应看 tick 相邻约差 1000 ms、RTC 连续走秒、TIM2 计数变化。TIM2 为 1 MHz、16 位计数器，约 65.536 ms 回绕，日志不是累计微秒数。该输出不能代替示波器测量时钟精度。
5. RTC 日期时间目前是 CubeMX 默认值，没有 SNTP 校时；后续 C08 再接校时，不把当前时间当作有效业务时间。

## 异常定位与待验证

- 启动日志完全没有输出：先确认串口接线、115200 和复位时序。SystemClock_Config 与 RTC 初始化早于 USART1；HSE/LSE 或 RTC 初始化失败时会停在原有 Error_Handler，不能只凭无日志判定是串口问题。用调试器查看调用栈和 RCC 状态，再按配置指南检查晶振，不自动切换时钟源。
- tick 在走而 RTC 不走：检查 LSE/RTC 时钟源及备份域配置；不要直接反复清备份域。
- TIM2 启动失败或 RTC 读取失败：日志会给出提示，用调试器定位 HAL 返回结果。
- 日志发送等待限制为 20 ms，限主循环短日志使用；C01 未启用调试串口命令接收。

编译仅证明源码和链接通过。LED 实际极性/周期、USART1 输出、LSE 起振及 RTC/TIM2 计数仍待上板验证。验证通过并反馈后再开始 C02。
