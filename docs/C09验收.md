# C09：MQTT、JSON 与远程命令

日期：2026-10-26。当前 C09 已实现并通过 Debug 编译和软件回放；电脑端已使用新部署账户验证云 Broker 的认证及临时主题 QoS 0 收发。**用户于 2026-10-26 确认 C09 验收通过。** 下文保留开发过程记录；除已记录日志外，不补写用户未提供的独立测量结果。 本轮不进入 C10，也不开发网站。

## 1. 本轮接入

- USART3 保持 115200、单字节中断接收和固定环形缓冲；发送使用中断，主循环推进 AT 状态机。
- Wi-Fi/SNTP 之后接 MQTT；SNTP 没有有效时间也可继续联网，未校时 ts=0。
- 使用 LinkID=0、TCP、QoS 0、Retain=false、Clean Session、Keep Alive=120。
- 连接且命令主题订阅成功后立即上报快照，之后默认 5 秒；周期可设 1～3600 秒。
- 在线报警、消警发送事件并尽快更新状态快照；离线不积存历史事件，恢复后只发当前状态。
- 保留取消自动 GMR、关闭 RTC 周期时间行的设置；GPS/OLED 本地卫星数显示不改，MQTT 不含 sat。

## 3. 启动指令

```text
AT
ATE0
AT+CWMODE=1
AT+CWJAP="本地配置的SSID","本地配置的密码"
AT+CIPSNTPCFG=1,8,"ntp.aliyun.com","ntp.sjtu.edu.cn","cn.ntp.org.cn"
AT+CIPSNTPTIME?
AT+MQTTCLEAN=0
AT+MQTTUSERCFG=0,1,"belt01","本地配置的MQTT用户名","本地配置的MQTT密码",0,0,""
AT+MQTTCONNCFG=0,120,0,"","",0,0
AT+MQTTCONN=0,"114.55.210.224",1883,0
AT+MQTTSUB=0,"fallguard/belt01/cmd",0
```

每条实际指令以 CR-LF 结束，上一事务完成后才能发送下一条。Wi-Fi 和 MQTT 账户配置的 TX/回显隐藏凭据。CLEAN 在无旧会话时返回 ERROR 可继续；其他 MQTT 事务失败进入恢复。

连接同时等待匹配 Broker 的 `+MQTTCONNECTED` 和最终 OK，允许两者任意先后。订阅最终确认前不允许业务上报。发送用普通 AT+MQTTPUB，原始 JSON 经 AT 转义，包含 CR-LF 的实际文本不超过 255 字节，NUL 另占 1 字节。

## 4. MQTTX 配置

| 设置 | 值 |
| --- | --- |
| 主机 | mqtt://114.55.210.224 |
| 端口 | 1883，关闭 TLS |
| MQTT 版本 | 3.1.1 |
| Client ID | fallguard-mqttx-pc；不要使用 belt01 |
| 用户名/密码 | 当前 MQTT 账户，不是 Dashboard 管理员账户 |
| 订阅 | fallguard/#，QoS 0 |
| 发布控制 | fallguard/belt01/cmd，QoS 0，Retain=false |

订阅全部主题时会看到自己发送的 cmd，这不是设备 ACK。设备只有 loc/alarm 上报，没有专用命令执行确认字段。发送控制前检查命令主题无历史保留命令。

位置示例：

```json
{"id":"belt01","ts":0,"lat":0,"lon":0,"fix":0,"st":"ok"}
```

报警示例：

```json
{"id":"belt01","ts":0,"ev":"fall","lat":0,"lon":0,"fix":0}
```

消警示例：

```json
{"id":"belt01","ts":0,"ev":"cancel"}
```

实际 ts 来自有效 RTC，否则为 0；实际经纬度为整数微度。失锁保留历史坐标但 fix=0，从未定位为零坐标且 fix=0。

## 5. 下行验收

逐条向 cmd 主题发送：

```json
{"cmd":"loc"}
{"cmd":"clear"}
{"cmd":"intv","v":1}
{"cmd":"intv","v":5}
```

loc 尽快请求最新快照；clear 仅在报警中解除，不会在正常状态触发报警；intv 从处理时重新计周期，范围 1～3600，MCU 重启恢复 5 秒。正常网络重连保留已设置的周期。

错误 JSON、缺参数、未知字段/命令、重复键、带尾随垃圾、字符串/小数/指数周期，以及 0、3601 均拒绝。完整下行载荷最多 127 字节，另留 NUL；固定命令 FIFO 为 4 项。按 URC 声明长度取载荷，载荷内部换行或 OK 不作为普通 AT 应答处理。

## 6. OLED 与日志

默认显示第 8 页 MQTT 页面；K1 循环原有 GPS/MPU/RTC 等页面，K2 保留本地测试/消警。MQTT 页显示连接阶段、Wi-Fi、上报周期、AT 发布成功/失败计数、命令丢弃/无效计数与 RX 丢字节。

PUB 表示 ESP 对发布事务返回成功，不能据此保证订阅者收到。LED 在 MQTT 订阅就绪后切正常模式，未在线仍为离线模式；报警优先快闪。

`DEBUG_LOG_MQTT` 控制连接/发布日志，`DEBUG_LOG_REPORT` 控制命令与业务 JSON；ESP/ESP_RX 与 RTC 启动/校时日志继续保留。`DEBUG_LOG_TIME_PERIODIC=0`，不会每秒输出重复 RTC 时间或未校准状态。

## 7. 恢复与限制

- MQTT 连接事务超时 30 秒，其他 MQTT 事务 10 秒；失败或接收失步后等待 30 秒，EN 拉低 100 ms 再启动。没有阻塞式等待。
- SNTP 有响应但时间无效，30 秒窗口结束后继续 MQTT，后续有限频率重试；SNTP 明确拒绝则本次 MCU 运行禁用后续 SNTP 并继续 MQTT，已有 RTC 保留。
- SNTP 事务无最终响应时先恢复 ESP，避免迟到 OK 污染后续事务；本次运行跳过后续 SNTP，从而允许重新联网后进入 MQTT。
- 在线事件 FIFO 为 4 项，满时记录丢弃；断线清空，重连只发当前快照。没有持久事件存储或离线补报。
- 本地最新报警状态先记录，再执行远程 clear，避免同一轮发生/解除报警时丢失事件；重复 clear 幂等，扶正再触发语义不变。
- 上报与校时共用一个 AT 事务通道，“立即”指下一次通道可用时调度，不保证严格端到端时延。QoS 0 也不保证每条事件送达。
