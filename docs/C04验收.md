## 接线

| MPU6050 模块 | STM32 |
|---|---|
| VCC | 3.3 V，按实际模块供电要求确认 |
| GND | 共地 |
| SCL | PB6 / I2C1_SCL |
| SDA | PB7 / I2C1_SDA |
| AD0 | GND，7 位地址固定 0x68 |
| INT、XDA、XCL | 本阶段不接 |

确认 SCL/SDA 有上拉至 3.3 V（先检查模块自带电阻），不能上拉至 5 V。沿用已有 CubeMX I2C1 400 kHz 配置，不改引脚。AD0 高时地址为 0x69，本阶段不自动扫描或更改地址；WHO_AM_I 期望仍为 0x68。

## 配置与校准范围

传感器加速度 ±2 g（16384 LSB/g）、陀螺仪 ±250°/s（131 LSB/(°/s)）。配置 DLPF=3，陀螺仪基准输出 1 kHz，SMPLRT_DIV=9，目标输出 100 Hz。配置并读回核对后，每隔至少 2 ms 检查 DATA_RDY；只有新数据才读取 14 字节并参与处理。没有 FIFO，不补造主循环错过的样本。

启动通过 tick 分阶段等待上电、复位和陀螺仪稳定。启动后请放稳模块约 3 秒，直到输出 gyro bias；其中 200 个有效新样本用作三轴陀螺仪均值零偏，之后从角速度中减去该偏置。校准不自动识别运动，若期间移动过，放稳后按复位重新校准。偏置只保存在 RAM，不写 Flash。

这不是完整 IMU 标定：加速度使用原厂名义系数，不扣除重力、不照搬上游 Z 轴系数；六面比例/零偏校准和腰带安装零位需本次实测记录。±2 g 仅用于初期驱动验收，不能据此宣称冲击测量合格；如运动中接近 ±2000 mg，记录后确认更大量程及其换算系数，再修改。跌倒阈值和阶段③语义仍留 C06 确认。

## 编译和烧录

VS Code 选择 Debug，执行 CMake: Configure，然后 CMake: Build，构建整个工程。烧录 build/Debug/fallguard.elf，复位后通过 USART1（PA9/PA10，115200 8N1）查看日志。不要对头文件或文档执行“编译当前文件”。

正常启动应见：

    === fallguard C04 ===
    [C04] HCLK=72000000 Hz LSE_READY=1
    [C04] MPU6050 @0x68: keep STILL for boot gyro calibration (~3s)
    [C04] WHO=0x68 cfg OK: 2g/250dps 100Hz DLPF=3; keep STILL
    [C04] gyro bias mdps=...,...,...

后续每 250 ms 输出一类诊断，一秒轮换完四类；四行不是同一时间的快照，示例数字只说明单位：

    [C04] A mg=0,0,1000
    [C04] G mdps=0,0,0
    [C04] K cdeg=0,0 T cdeg=3653
    [C04] N=100 dt=10 max=12 tick=3450

| 字段 | 含义 |
|---|---|
| A mg | X/Y/Z 加速度，1000 = 1 g；保留重力 |
| G mdps | 扣除启动零偏后的 X/Y/Z 角速度，1000 = 1°/s |
| K cdeg | Kalman X/Y 角度，100 = 1°，不是已标定的身体倾角 |
| T cdeg | 芯片内部温度，3653 = 36.53°C，不代表人体温度 |
| gyro bias mdps | 本次启动测得的三轴零偏 |
| N | 校准结束后处理的有效样本总数，校准 200 点不计入 |
| dt、max | 最近及本次启动最大样本间隔，单位 ms；首样本 dt=0 |
| tick | 最新样本的 HAL tick，单位 ms |

日志不使用浮点 printf。每秒对比 N 差和 tick 差，实际处理频率为 ΔN×1000/Δtick；正常应接近 100 Hz，dt 会因毫秒刻度、软件 I2C 刷屏、同步串口打印而有抖动。持续明显不足或 max 明显增大时，保留日志排查；寄存器配置为 100 Hz 不等于已验证实际处理率。

## 上板检查

1. 静止启动：确认 WHO/config 成功、约 3 秒后有偏置及持续变化的 N。静放时 G 应在零附近波动，A 合模应接近 1000 mg。记录偏置、抖动和实际频率，不把示例中的精确零当成要求。
2. 六面静放：依次让传感器的 ±X、±Y、±Z 轴朝上，对应轴分别应接近 ±1000 mg，其余轴近零。记录六组数据，核对轴箭头和符号，尤其确认 Z 没有使用上游私有校正系数。
3. 慢速绕 X、Y 转动：观察对应 G 的符号和 K 的变化，再静置观察是否稳定。以 Z 朝上的初始姿态测试约 45°及 90°。本算法 X 角范围约 ±90°、Y 角范围约 ±180°，pitch 跨 ±180°时允许数值跳号；没有融合磁力计，不输出航向角。任意姿态下单轴角不能直接解释成身体倾角。
4. 固定到腰带并记录安装：写下传感器 +X/+Y/+Z 分别朝向人体哪里，记录直立、前倾、侧倾和横放时的三轴 A 与 K，供 C06 选择直立参考重力方向；本阶段不自动设置身体倾角零位。
5. 同时翻页、按 K2：OLED、LED 和按键应继续响应；K2 仍只是测试报警开关。观察 N 与 max，确认刷屏和按键日志对采样的实际影响。本阶段没有跌倒报警判定。
6. 量程观察只需手持模块平稳转动、轻晃，不需要真人跌倒。记录是否出现 A 接近 ±2000 mg 或 G 接近 ±250000 mdps 的削顶；陀螺仪校正后读数略超名义边界不能单独证明未饱和。

若显示 MPU stopped，先看紧邻其前的详细诊断：

| 日志 | 定位 |
|---|---|
| MPU W reg=0x6B + failed at device reset | 首次复位寄存器写入失败，尚未读取 WHO_AM_I |
| MPU R reg=0x75 | 读取器件 ID 的 I2C 事务失败 |
| MPU WHO_AM_I=... expected=0x68 | I2C 读取成功，但 ID 不符合当前驱动；不要直接放宽检查 |
| MPU W reg=... | 对应配置寄存器写入失败 |
| MPU verify reg=... got=... expected=... | I2C 读取成功，但配置读回不符 |
| MPU R reg=0x3A / 0x3B | 采样时读取数据就绪标志 / 数据失败 |

通信错误会带 HAL、err 和 BUSY。HAL=1/2/3 分别为 HAL_ERROR/HAL_BUSY/HAL_TIMEOUT；err 是本工程 HAL 的位掩码：0x00000004 为应答失败 AF（可能在地址或数据阶段），0x00000020 为超时，0x00000001 为总线错误，0x00000002 为仲裁丢失。BUSY 是失败时的外设状态位，BUSY=1 不能单独证明哪根线被拉低。HAL 状态与 err 应一起判断。

检查供电、共地、上拉、SCL→PB6、SDA→PB7 和 AD0→GND。需要时测模块供电，以及总线空闲时 PB6/PB7 是否都接近 3.3 V。OLED 使用 PB4/PB5 软件 I2C，其正常不代表 MPU 所在的硬件 I2C1 正常。初始化/读取失败后停止本模块采样，不循环阻塞重试；断电检查接线后重新上电，并提供完整新日志。OLED/按键/LED 仍由主循环维护。若 N 不再增长，即使没有总线错误也不能视为采样正常，应一并提供状态日志。
