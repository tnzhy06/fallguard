# C05 GPS 接入与验收

## 依据与范围

在 C04 基础上移植 [MaJerle/lwgps](https://github.com/MaJerle/lwgps)（[开源项目地址](开源项目地址.md)中的第二项）。版本、配置及 MIT 许可证见 [移植记录](../ThirdParty/lwgps/README.md)。

核对资料：

- [模块数据手册](ATGM336H-5N模块资料/使用手册/ATGM336H-5N模块数据手册.pdf)第 10～12 页：UART、电平、出厂 9600 8N1、默认 1 Hz 更新。
- [模块使用手册](ATGM336H-5N模块资料/使用手册/ATGM336H-5N模块使用手册.pdf)第 5～11 页：GN/GP/BD 前缀、GGA 海平面海拔、RMC UTC、GSV 信号及坐标换算。

用户已将实际模块设为 **115200**，USART2 同为 **115200 8N1**。本阶段仅接收 NMEA，不发送模块配置命令。显示 UTC、经纬度、海拔、卫星数、HDOP、四档信号；不输出速度。GPS UTC 不加时区、不写 STM32 RTC，网络校时留到 C08。

## 接线与烧录

| GPS 成品板 | STM32 |
|---|---|
| TXD | PA3 / USART2_RX，必接 |
| RXD | 本阶段可不接；双向通信时接 PA2 / USART2_TX |
| GND | 共地 |
| VCCIN | 按实际成品板和使用手册供电；裸模块 VCC 为 2.7～3.6 V |
| PPS | 本阶段不接 |

UART 为 3.3 V TTL。USB-TTL 回放时断开 GPS TXD，只保留一个发送端驱动 PA3。

VS Code 选择 Debug，执行 CMake: Configure、CMake: Build，烧录 [fallguard.elf](../build/Debug/fallguard.elf)。USART1 调试串口同为 115200 8N1，当前已重新接入 MPU6050，复位后保持设备静止约 3 秒采集陀螺零偏；实时页见 [MPU6050 显示验收](MPU6050实时显示.md)。

启动日志包含：

```text
=== fallguard C05 ===
[C05] GPS: TX->PA3, USART2 115200 8N1, stale=5000ms
```

## OLED 与按键

当前 K1 循环六页：**MPU6050（默认）→ GPS 信息 → GPS SIGNAL → 字符演示 → 中文演示 → 图形演示 → MPU6050**。K2 在任意页开启/取消本地测试报警。

GPS 信息页示例：

```text
GPS LIVE  SAT:5
UTC 2016-12-14
    08:48:52
LAT +22.615755
LON +114.141317
ALT +89.70m
HDOP 3.10
K1:PAGE  K2:ALARM
```

- LIVE：当前 fix=1。WAIT：从未取得有效位置，经纬度/海拔显示 --，不将零坐标伪装成定位。
- LAST：当前 fix=0，显示上次有效经纬度和海拔，末行显示 LAST AGE Ns。UTC 和 HDOP 依据各自有效位显示，占位符表示不可用。
- LAT/LON 为十进制度；北/东为正，南/西为负。整数微度保存，六位小数仅是显示精度。
- ALT 为 GGA 的海平面高度，整数厘米保存，可为负值；不将大地水准面差值当成海拔。
- SAT / USED 为最近 GGA 中参与定位的卫星数；VIEW 为最新有效 GSV 的可见卫星数，二者不同。失锁时 SAT 可能仍保留最近值，不能据此认定定位有效。
- HDOP 来自 GSA，是水平精度衰减因子，不是射频信号强度；该版本不解析 GGA HDOP，只有 GGA/RMC 时 HDOP 显示 --。

GPS SIGNAL 仅用 0～3 个实心信号格表示档位，不显示“无／弱／中／强”文字；同时显示最大 C/N₀、可见卫星数、有数值报告的卫星数及 fix。按用户已确认的规则：

| 档位 | 最大 C/N₀ | 实心格 |
|---|---|---|
| 无 | 无有效数据、已过期或数值为 0 | 0 |
| 弱 | 1～29 dBHz | 1 |
| 中 | 30～39 dBHz | 2 |
| 强 | 40～99 dBHz | 3 |

空信号字段不计入数值报告数，00 计入报告数但分级为“无”。缺少有效值显示 --；缺少完整 GSV 组显示 WAITING FOR GSV。即使未定位，也可能收到有效信号值。这是项目显示分级，不代表位置精度或接收机统一性能标准。

## 数据与过期规则

- ISR 仅搬运一字节、重挂接收并记录接收错误；主循环每次最多消费 128 字节。帧从 $ 开始，要求 CRLF 与有效校验和，限制总长和字段长度。
- GGA 质量 1/2/3、RMC=A 且二者各自均未达到 5000 ms 未有效更新时，fix=1。任一无效或过期则 fix=0，保留历史经纬度和海拔；单独持续收到另一种句子不能维持 fix。
- UTC 来自字段合法的 RMC，不依赖 fix；RMC 过期或接收故障后撤销 UTC 有效位。HDOP 也独立采用 5 秒新鲜度。
- GSV 必须完成同一 talker 的所有分句并通过校验，可合并连续的 GP/BD 等星座组，最多 48 条卫星记录；在后续非 GSV 句子到达时发布。缺句、错序、字段越界或坏校验不发布半组。
- 信号自最后有效 GSV 分句起 5000 ms 过期，与 fix 分开判断。UART 错误或环形缓冲溢出撤销当前数据有效性，等待完整新数据恢复。

## 串口日志与模拟回放

GPS 日志默认关闭，需在 [debug_config.h](../BSP/debug_config.h) 开启所需分类（见 [输出配置](调试串口输出配置.md)）。启用后，GPS 每隔至少 250 ms 输出一行，共 7 个时隙；为 MPU6050 实时输出让出短时隙，轮次时间不固定。GPS 各行不是同一时刻的快照。关注 rx/gga/rmc 和 crc/bad/drop/uart。

使用 [模拟 NMEA 数据](C05_GPS模拟数据.nmea)，发送端 115200 8N1，整组按原始文本发送，保留 CRLF，每秒循环一次。数据取自手册示例，用于室内验证解析和显示，日期及坐标不代表设备当前位置。

预期解析结果：

```text
fix=1 has=1 sat=5
lat_udeg=22615755 lon_udeg=114141317
UTC=2016-12-14 08:48:52 valid=1
alt_cm=8970 hdop_x100=310 hv=1
GSV view=11 cn0_n=5 max_dbhz=31 valid=1 gv=1 level=MEDIUM
```

lat_udeg/lon_udeg 为整数微度，alt_cm 为厘米，hdop_x100 为 HDOP 乘 100。crc 为所处理语句的校验失败数，bad 为格式/字段错误数，drop 为溢出丢字节数；uart/err 记录 UART 错误，err 的高位 80000000 表示接收重挂失败。

## 上板验收

1. 无输入时默认 GPS WAIT，坐标/海拔为 --，信号为 0 格，rx=0。
2. 循环模拟数据后检查 UTC、经纬度、海拔与上述预期一致；K1 进入信号页应显示两格、31 dBHz、VIEW 11、CN0 N 5。
3. 停止发送，最后有效数据满 5 秒后应变 LAST、UTC/HDOP 变 --、信号变为 0 格；坐标与海拔保留，年龄增加。重新发送后恢复 LIVE。
4. 连续接收时切换 K1 与 K2，确认 GPS、OLED、LED 同时工作，drop/uart 不持续增长。
5. 接回真实 GPS，先确认 rx 与 gga/rmc 增长，再到安全开阔位置等待定位；检查位置和海拔是否合理。室内不定位不能直接判定硬件故障。
