# C07 JQ8900 一线语音验收

C07 已编译通过，软件协议回放通过。2026-10-26 用户确认 C07 验收通过；未提供独立示波器测量记录，不补写实测脉宽。上一步代码已推送 GitHub：[`df9cbcd`](https://github.com/tnzhy06/fallguard/commit/df9cbcd92f17dfab7f02cec08ed2dfcc8c2c5a50)。用户要求将本轮已验收代码推送 GitHub，并进入 C08 校时与 RTC。

## 接线与文件

| STM32/模块 | 连接与要求 |
|---|---|
| PB0 / JQ_SDA | 接 JQ8900 的 **VPP** 一线输入 |
| PB1 / JQ_BUSY | 接 BUSY；手册定义播放高、空闲低 |
| GND | STM32、JQ8900、电源共地 |
| JQ8900 DC-5V | 按手册第 4 页供电，不能超过 5.2 V |
| SPK+ / SPK- | 扬声器接两端，按模块手册匹配；不要把 SPK- 当地线 |
| FLASH 根目录 | 用户已确认存放 **00001.mp3** |

协议依据为 [JQ8900语音模块16p.pdf](JQ8900语音模块16p.pdf)，实际共 19 个物理页；一线协议在第 7～11 页，引脚表在第 4 页。PB0 不接 RX/TX，不使用两线串口协议。STM32 信号保持 3.3 V。

## 当前行为

- 上电后非阻塞等待 1 秒，再依次发送选择 FLASH、停止、音量 20。1 秒是项目参数，手册未保证模块必定在此时间内就绪。开机不主动播放提示音。
- 未报警时短按 K2：进入 TEST ALARM，播放第 1 首；倾斜满足现有 60°/1 秒规则时进入 FALL DEMO，同样播放第 1 首。
- 观察到 BUSY 高，再观察到低，若报警仍保持则再次选曲。没有观察到高电平时停在等待状态，便于排查接线/文件/时序，不盲目重发。
- 报警时短按 K2：停止语音并清除本地报警。保持当前正在发送的字节完整，丢弃尚未发送的选曲字节，在满足字节间隔后优先发停止命令。不是按键瞬间中断一线波形；模块实际停止响应仍需测量。
- K2 消警后的扶正重新待命规则不变，GPS、MPU 实时显示及串口输出开关继续工作。

一线输入没有本实现可读取的命令 ACK。日志中的“queued”只代表排队，“init sent”只代表初始化命令已发送，均不等于真实播放成功。BUSY 引脚原有上拉未变，断线也可能读到高电平，必须核对实际接线。

## 波形与命令

| 项目 | 本轮设置 | 手册依据 |
|---|---|---|
| 位序 | 每字节 LSB 先发 | 第 7 页 |
| 空闲/字节前 | 高；字节前高 1000 µs | 第 10 页示例 |
| 引导 | 低 4000 µs | 第 7 页 >2 ms，第 11 页建议 4 ms |
| 数据 0 | 高 500、低 1500 µs | 第 7 页短/长 >400/>1200 µs，比例 1:3 |
| 数据 1 | 高 1500、低 500 µs | 第 7 页比例 3:1 |
| 字节结束/间隔 | 回高，主循环等待至少 12 ms 再开始下一字节 | 第 11 页 >10 ms |

第 10 页的 210/500 µs 示例与第 7 页绝对脉宽图不一致。本实现选用 500/1500 µs 满足图中下限与 1:3 比例，并未照搬 C51 示例的整字节关中断。单字节标称 21 ms，三字节选曲到末位结束约 87 ms；实际波形还受 IRQ 和主循环调度影响，须示波器确认。

命令字节均为十六进制原始数字，不是 ASCII：

| 操作 | 字节 |
|---|---|
| 选择 FLASH | `1A` |
| 停止 | `13` |
| 音量 20 | `0A 02 00 0C` |
| 播放第 1 首 | `0A 01 0B` |

选曲每次先清空数字，文件名为五位数字，但指令不必补齐前导零，遵循手册第 9 页选曲 2/15 的示例。重复提示由 BUSY 高转低后重新选曲实现；未使用 `0E`，未套用两线 UART 章节的循环模式数字。

## 验收步骤

1. 编译 Debug，烧录 [fallguard.elf](../build/Debug/fallguard.elf)。MPU 平放静止约 3 秒完成原有启动零偏采集。
2. 确认开机不播放音频。按 K2，显示 TEST ALARM，听到 `00001.mp3`，串口出现选曲与 BUSY 变化事件；播放结束后应继续重复提示。
3. 再按 K2，确认语音停止、报警页退出，等待期间不出现迟来的选曲。可在刚按下测试键后立即取消，验证发送中消警。
4. 扶正后，将任一角倾斜至 60°以上并保持 1 秒，确认 FALL DEMO 同样播放报警；K2 消警后仍需扶正才能再次自动触发。
5. 播放与发命令期间切换 OLED 页面，确认按键、GPS 解析和 MPU 采样持续工作。可在 [debug_config.h](../BSP/debug_config.h) 临时开启 `DEBUG_LOG_GPS_STATS` 检查接收/丢字节/UART 错误，保持 `DEBUG_LOG_MPU_ANGLES=1` 检查 MPU 采样间隔。记录语音开启前后 `dt/max` 与错误计数变化。
6. 示波器/逻辑分析仪观察 PB0：引导低约 4 ms，短/长约 500/1500 µs，LSB 先发，字节间高电平大于 10 ms；同时检查 PB1 实际播放高、空闲低。先确认信号识别，再评价重复播放行为。

若显示 `VOICE WAIT BUSY` 且无声音，优先检查 VPP 接线、共地、根目录文件名、FLASH 存储及真实波形。`VOICE BUSY HIGH` 只表示读到了 BUSY 高；`VOICE TIMER ERROR` 表示 TIM3 启动失败。初始化期间显示 `VOICE INIT`。

## 修改位置与验证结果

- [bsp_jq8900.c](../BSP/bsp_jq8900.c) / [.h](../BSP/bsp_jq8900.h)：一线发送器，时序参数集中在头文件；固定缓冲，无 DMA、动态分配或长阻塞。
- [app_voice.c](../App/app_voice.c) / [.h](../App/app_voice.h)：初始化、报警选曲、BUSY 重播、消警；曲目 `APP_VOICE_ALARM_TRACK=1`、音量 `APP_VOICE_VOLUME=20`。
- [app_main.c](../App/app_main.c)、[app_ui.c](../App/app_ui.c)：调度与报警页语音状态；[debug_config.h](../BSP/debug_config.h) 的 `DEBUG_LOG_JQ=1` 控制简短语音事件。
- `fallguard.ioc` 与 CubeMX 生成的 `tim`、`main`、中断声明/实现：新增 TIM3 内部 1 MHz 定时，PSC=71、ARR 预装载关闭、更新中断优先级 0。TIM2 用途和物理引脚配置不变。手工 Core 接入均在 USER CODE 块内。
- 根 `CMakeLists.txt` 加入两个新模块；HAL 与生成的 `cmake/stm32cubemx` 未修改。

Debug 编译成功：RAM **6216 B**，FLASH **59948 B**，编译数据库保留在原 `build/Debug`。修改源码的 `-Wall -Wextra -Werror` 检查通过。软件回放覆盖全部 256 字节、手册选曲/音量示例、发送中停止、计时回绕、定时器失败、初始化、BUSY 重播及启动前取消，见 [tests/jq8900/README.md](../tests/jq8900/README.md)。原调度器默认/静默/全开日志的语音状态传递，以及实际 OLED/UI 回放也通过。

软件回放采用理想定时，不能验证真实 IRQ 延迟、音频识别或电气行为。用户已确认验收通过，后续进入 C08 校时与 RTC。
