# 简单跌倒演示验收

用户已确认以简化姿态法替代原三段判据：**Roll 或 Pitch 的绝对值 ≥60°，持续 1000 ms 即报警。** 不要求先失重、再冲击或连续静止；缓慢放倒同样触发，适用于本课程演示，不将其解释为准确的人体跌倒判断。

## 实际规则

| 情况 | 行为 |
|---|---|
| 两个角绝对值均 <60° | 待命 |
| 任一角绝对值 ≥60° | 开始计时，OLED 显示 HOLD |
| 保持期间两角均恢复 <60° | 清除计时，重新待命 |
| 达到 1000 ms | OLED 反色显示 FALL DEMO，LED 快闪，报警锁定 |
| 报警后重新扶正 | 报警仍保持，等待 K2 消警 |
| 按 K2 消警 | 关闭报警；若仍倾斜，显示 RAISE TO REARM，不能自动重报 |
| 消警后两角均 <60° | 重新待命，下一次倾斜可再次触发 |
| 未报警时按 K2 | 立即进入 TEST ALARM，保留手动演示功能 |

报警控制本地 OLED/LED，不等待原先 10 s 窗口；C07 已接入语音，见 [C07验收.md](C07验收.md)，网络上报留在后续模块，不修改现有 MQTT topic 或 JSON 字段。消警后 LED 回到原有网络未连接常亮模式。

MPU 未就绪、没有首个样本或通信失败时不自动判定。仅新样本推进计时；重复/冻结样本不会单独触发报警。通信失败或一整个保持时间未获得新样本会清掉正在进行的计时，新数据恢复后重新开始。已锁定报警不会因传感器故障自动清除，仍可按 K2 消警。小于此间隔的采样缺口不单独做复杂补偿。

## 测试步骤

1. 编译 Debug、烧录 [fallguard.elf](../build/Debug/fallguard.elf)，模块平放且保持静止约 3 秒，等待 MPU6050 LIVE。
2. 正常情况下 Roll/Pitch 接近 0°，底部显示 FALL:READY。当前角是模块坐标角，测试以模块平放为正常参考，不自动设置身体直立零位。
3. 缓慢倾斜模块，使任一角绝对值达到 60°以上；底部应出现 HOLD:xxx/1000ms。保持约 1 秒，显示 FALL DEMO、LED 快闪。
4. 短按 K2，报警消除；仍放倒时应显示 RAISE TO REARM，继续等待也不重报。
5. 扶正，确认两个角均小于 60°，恢复 FALL:READY。再次放倒，应能再次触发。
6. 倾斜后不到 1 秒就扶正，应清掉计时；平放时按 K2，显示 TEST ALARM，再按 K2 取消。

Roll 正/负方向、Pitch 正/负方向都支持。不需要摔落设备或让人摔倒。OLED 更新约 100 ms，实际观察到的触发时刻还包括滤波响应和页面刷新时间。

## 参数、日志与文件

参数集中在 [App/app_fall.h](../App/app_fall.h)：

```c
#define APP_FALL_ANGLE_DEG 60
#define APP_FALL_HOLD_MS   1000U
```

这是当前已确认的演示规则；修改数值会改变触发条件。判定代码在 [app_fall.c](../App/app_fall.c)，只有待命、保持、报警、等待扶正四种简单状态，无浮点计算或动态内存。输入使用现有 BSP 的 Roll/Pitch 整数百分之一度，不重复实现姿态融合。

[app_main.c](../App/app_main.c) 调度判定、K2 控制及 OLED/LED；[app_ui.c](../App/app_ui.c) 增加保持进度、扶正提示和自动/手动报警覆盖页。GPS、八项 MPU 实时显示和调试分类继续保留，不恢复之前的六面采集功能。

[debug_config.h](../BSP/debug_config.h) 中新增 DEBUG_LOG_FALL，默认 1，记录报警、消警、扶正重新待命三类事件，不逐样本刷屏。设置为 0 只关闭事件打印，不关闭检测；DEBUG_OUTPUT_ENABLE=0 可让串口完全静默，检测与显示仍运行。

```text
[FALL] alarm source=AUTO; K2 to cancel
[FALL] canceled; raise board to rearm
[FALL] upright; ready
```
