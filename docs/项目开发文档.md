## 1. 项目概述

做一条腰带式装置，佩戴者可被定位、可被判断状态。跌倒时本地中文语音报警，并通过网络把位置与跌倒事件上报服务器。

课程展示项目，目标是**功能跑通、代码简洁**，不做产品级可靠性设计（不做电源设计、不设计外壳）。

### 1.1 需求 → 实现映射

| 需求（需求文档） | 实现方式 |
|---|---|
| 解析 JSON，MQTT 通信 | ESP-01S 跑 AT MQTT 固件，STM32 发 AT 指令；上行 JSON 用固定缓冲区拼装并检查长度，下行用极简解析 |
| 解析 NMEA 获取位置 | ATGM336H 接 USART2，移植 `lwgps` 解析 |
| 加速度判断跌倒 | MPU6050 接 I2C1，三段式时序判据（见 5.2） |
| 上报经纬度 / 跌倒提示 | 周期上报 + 事件上报，两个 MQTT topic |
| 跌倒时中文语音报警 | JQ8900 一线串口，播放预存中文语音 |
| 实时发送位置和状态 | 10 s 周期上报（可被下行命令修改） |
| 区分正常躺下和跌倒 | 用失重、冲击、姿态时序减少误报，效果须实测标定（见 5.2） |
| OLED 显示时间/网络/GPS 强度/位置 | 3 页界面 + 按键翻页（另加一页算法调试页），见第 6 章 |
| 其他创新性设计 | 见 10.2 |

**User Label 说明**：这是 CubeMX 里给引脚起的标签，生成后会在 `Core/Inc/main.h` 里变成 `#define LED_Pin GPIO_PIN_8` / `#define LED_GPIO_Port GPIOA` 这样的宏，代码里写 `HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, ...)`，不写死 `GPIOA, GPIO_PIN_8`。
**外设引脚（USART/I2C/LSE）不用设标签**——CubeMX 已经用 `huart1`、`hi2c1` 这些句柄管理了。配置步骤见 `CubeMX配置指南.md` 第 4.0 节。

**冲突检查结果**：以上分配互不冲突。PB10/PB11 同时是 I2C2，本方案 I2C2 不用；PC10/PC11(UART4)、PC12/PD2(UART5) 空余，可作备用。

### 3.3 两个必须提前知道的坑

1. **PB4/PB5 不是 STM32F103 的硬件 I2C 引脚。** F103 的 I2C1 只在 PB6/PB7（或重映射 PB8/PB9），PB4/PB5 没有 I2C 复用功能。所以 OLED **只能用软件 I2C**——正好 `zeruns` 的驱动支持软件 I2C 模式，符合要求，但硬件 I2C 那条路走不通。
2. **PB4 上电默认是 JTAG 的 NJTRST。** 想把它当普通 GPIO 用，必须在初始化里关掉 JTAG、保留 SWD：
   `__HAL_RCC_AFIO_CLK_ENABLE(); __HAL_AFIO_REMAP_SWJ_NOJTAG();`
   只影响 PB3/PB4/PA15，SWD（PA13/PA14）不受影响，调试照常。

### 3.4 硬件连接注意

- 所有模块与 STM32 共地，区分模块电源电压与 IO 电平。JQ8900 手册第 3～4 页说明 IO 为 3.3 V；模块 DC-5V 引脚标注不超过 5.2 V。其第 12 页“串 1 kΩ”针对 **5 V 主机逻辑**，不能改写成“模块用 5 V 供电就要串电阻”。
- ESP-01S 使用稳定的 3.3 V 电源，不能接 5 V。供电能力按至少 500 mA 预留，确认现有开发板稳压器和连接线能承受 WiFi 瞬时负载；无需为本课程项目另做电源设计。供电建议可参见 [Espressif 硬件说明](https://www.espressif.com/en/products/socs/esp8266ex/resources/)。
- ESP-01S 的 CH_PD/EN 接 PB12，默认高。启动或连续 AT 超时时，可用状态机拉低 100 ms 后拉高并等待启动；这属于芯片使能复位，不是切断模块 VCC。等待期间本地任务继续运行。
- OLED 的 PB4/PB5 使用开漏输出，必须确认模块板已有上拉到 3.3 V 的电阻；没有则外接。STM32F1 输出模式下的 `GPIO_PULLUP` 不会开启内部上拉，不能靠该配置维持总线高电平。

## 4. 软件架构

### 4.1 分层

```
App 层     app_main(调度器+系统状态机) / app_fall / app_report / app_ui / app_json
BSP 层     bsp_oled / bsp_mpu6050 / bsp_gps / bsp_jq8900 / bsp_esp / bsp_key / bsp_led / bsp_delay / bsp_rtc
第三方     lwgps(NMEA) / 所选 OLED 驱动配套字库
HAL 层     CubeMX 生成 + STM32F1 HAL
```

### 4.2 不用 RTOS 的调度方式

主循环使用 `HAL_GetTick()` 时间片轮询，不用 RTOS。App 仅直接使用此 tick 接口，外设访问通过 BSP；RTC 日期时间读写由 `bsp_rtc` 封装。

```c
typedef struct { void (*fn)(void); uint32_t period; uint32_t last; } task_t;

static task_t tasks[] = {
    { gps_poll,    10, 0 },
    { imu_poll,    10, 0 },
    { net_poll,     5, 0 },
    { key_scan,    20, 0 },
    { ui_refresh, 100, 0 },
    { report_task,100, 0 },
};
```

`imu_poll` 每次取得有效新样本后，立即调用跌倒状态机；不能再用一个 20 ms 任务只看“最新值”，否则会跳过部分样本。上报任务按时间戳判断周期，默认 10 s；报警撤销窗口和其他期限也按 tick 判断，不靠任务执行次数计秒。

任务到期用无符号差值 `(uint32_t)(now - last) >= period` 判断，允许 tick 回绕。上述周期是调度目标，必须测量实际任务耗时和相邻 IMU 样本间隔；超时后不要连续读取同一时刻的数据伪装成补采样。

OLED 100 ms 只更新界面内容，实际传输在主循环中分小块推进。100 kHz I2C 下整屏 1024 字节仅数据和 ACK 就约 92 ms，不得一次阻塞刷新整屏；每批字节数按实测耗时限制。AT 等待、JQ8900 引导/字节间隔全部用状态机推进，禁止业务阻塞式长延时。普通 GPIO 波形发送若无法满足采样和串口接收要求，再在 C07 选择定时器边沿方案；不改引脚、不用 DMA。

### 4.3 串口接收：单字节中断 + 环形缓冲

三个串口的数据率都不高，**都不用 DMA**：

| 串口 | TX | RX |
|---|---|---|
| USART1 调试 | 短日志 printf（GCC/newlib 重定向 `_write`） | 单字节中断，只用于收上位机的测试命令；用不上可以干脆不开 |
| USART2 GPS | 基本不用 | 单字节中断 → 环形缓冲 → 主循环喂 lwgps |
| USART3 ESP | 阻塞发送 AT 指令 | 单字节中断 → 环形缓冲 → AT 状态机解析 |

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart == &huart2) { rb_push(&gps_rb, rx2); HAL_UART_Receive_IT(&huart2, &rx2, 1); }
    if (huart == &huart3) { rb_push(&esp_rb, rx3); HAL_UART_Receive_IT(&huart3, &rx3, 1); }
}
```

**实现边界**：115200 8N1 的满速字节率为 11520 B/s；接收中断只搬数据，CPU 占用需实测，不预先宣称固定低于 3%。USART1 RX 仅在需要测试命令时启用。

必须处理 UART 的 ORE 等接收错误并恢复单字节接收；环形缓冲由中断生产、主循环消费，写满时记录溢出并让对应解析器放弃不完整帧。GPS 重新寻找完整 NMEA 句并校验，ESP 按 URC 头和载荷长度解析。不得在丢失 MQTT 载荷后只靠“下一处 CRLF”判定已恢复同步；必要时使当前事务失败并重新建立会话。

JQ8900 不得整字节关闭全局中断。UART 中断需要在语音命令发送期间继续接收，AT 响应和 URC 仍可能到达。字节间隔也应让出主循环；不得假定丢失的命令必定由服务器重发。所有串口保持单字节中断与环形缓冲方案，不设 DMA 退路。

### 4.4 系统状态机

```
INIT ──► WIFI_CONNECT ──► SNTP_SYNC ──► MQTT_CONNECT ──► RUN
             ▲                                              │
             └──────────── 断线重连（net_poll 里检测）──────┘
```

`RUN` 表示 MQTT 已连接且命令 topic 订阅成功，才允许上报。网络未通时本地功能（GPS、跌倒检测、语音、OLED）继续运行，OLED 显示“离线”。SNTP 在限定重试后失败应继续进入 MQTT_CONNECT，保留“时间未校准”状态；具体重试期限在 C08 验证。离线事件是否补报见 10.3，不预设存在服务器重发或持久队列。

## 5. 关键模块设计

### 5.1 GPS 解析（移植 lwgps）

- 将 UART 环形缓冲中的字节在主循环喂给 `lwgps`，固定所用版本与配置，不引入动态内存分配。
- ATGM336H 原厂默认 9600 8N1；用户已将实际模块波特率设置为 115200，当前 USART2 同为 115200 8N1。模拟发送端也须使用 115200。按实际输出识别 GN/GP/BD 等 talker 前缀，不把 `GNGGA`、`GNRMC` 写死为唯一合法句子。GGA 提供坐标、定位质量、参与定位卫星数、HDOP 和海平面海拔，RMC 提供有效状态与 UTC 日期时间，GSV 提供可见卫星及信号值。C05 使用 lwgps 解析 GGA/RMC/GSA/GSV，HDOP 从其支持的 GSA 字段读取；本项目不展示速度。
- 原始 NMEA 坐标为 `ddmm.mmmm`，例如 `22 + 36.9453/60 = 22.615755`；**lwgps 的 latitude/longitude 已是十进制度**，不能再做一次度分转换。输出时按南/西为负换成有符号整数微度。海拔以整数厘米保存，显示时拆成米的整数和小数，不启用浮点 printf。
- BSP 保存上一次有效坐标及更新时间。无效定位时不把无效 NMEA 坐标覆盖进去；上报 `fix=0` 并沿用上次有效坐标。开机从未定位时坐标缓冲初始为 0，此时 `fix=0`，服务器不得把 (0,0) 当成真实位置。
- 用户已确认采用 **5 秒**过期规则：GGA 质量为 1/2/3、RMC=A 且两者均在 5000 ms 内更新时，`fix=1`；任一失效或达到 5000 ms 未有效更新则 `fix=0`。保留上次有效经纬度与海拔，OLED 标记 LAST 和位置年龄；首次定位前显示 WAIT 与占位符。`fix` 对外归一为 0/1，不直接照搬 GGA 的多值质量码。
- 信号来自校验通过的完整 GSV 组，以最大 C/N₀（dBHz）显示。用户已确认四档：无＝无有效数据、过期或值为 0；弱＝1～29；中＝30～39；强＝40～99。信号独立采用 5 秒过期规则，不用卫星数或 HDOP 代替，也不作为 fix 条件。GPS UTC 原样显示，不加 8 小时、不写 RTC。

### 5.2 跌倒检测（本项目算法核心）

**状态：待 C06 标定确认。** 用户要求阶段③暂不选定新时间窗口；下表中的经验值不等于已验证算法，未定项必须先确认，不能由 Agent 补成正式阈值。

**采样与安装**：目标 100 Hz，每个有效样本参与一次判定。先固定 MPU6050 在腰带上的安装方向，记录佩戴者直立时的传感器参考轴/重力方向，再标定倾角零位；不能将任意一个未经安装校准的单轴角直接作为身体倾角。

**输入量**：
- 合加速度 `a = sqrt(ax² + ay² + az²)`，单位 g。
- `tilt` 为身体直立参考轴与估计重力方向的夹角，直立约 0°、横躺约 90°。静态重力可由加速度估计，剧烈运动时加速度还包含运动分量，需结合角速度和滤波状态判断。
- `gy` 在调试页表示陀螺仪三轴模长，单位 °/s，不是单独 Y 轴的 `Gy`。原有 30/90 °/s 仅作观察参考，未批准为额外触发条件。

**候选时序判据**：

| 阶段 | 已记录的候选条件 | 时限/待确认项 |
|---|---|---|
| ① 失重 | `a < 0.6 g` 连续 ≥80 ms | 起点及采样间断的处理在 C06 固定 |
| ② 冲击 | 失重段后出现 `a > 2.0 g` | 原候选为自①起 1.5 s 内；须固定计时起点 |
| ③ 姿态确认 | `tilt > 60°`，`a` 回到 0.7～1.3 g，并持续静止 | **待 C06 确认：原文同时要求“②起 3 s 内”与“静止持续 3 s”，两者冲突，不能照此实现** |

C06 需分别确定进入姿态确认的期限、连续静止时长，以及静止的角速度/变化量条件。加速度模长接近 1 g 不能单独证明静止。失重不足持续时间、等待冲击、等待姿态、连续确认被打断等情况的转移与复位规则也需一并定稿；不把“某一帧暂不满足”一概当作超时。

缓慢躺下通常缺少明显失重和冲击，时序判据有助于减少误报，但快躺、坐下、跳跃、装置晃动及部分真实跌倒都可能造成误报或漏报。必须以实测数据验证，不能宣称正常躺下“永远不会触发”。

**确认后的交互**：保留 10 s 人工撤销窗口。算法确认后立即本地中文语音提示；窗口内 K2 取消并停止报警，联网时上报 `cancel`；窗口结束未取消则联网时上报 `fall` 并持续本地报警。K2 测试报警沿用这套交互。离线期间的事件补报策略待第 10.3 节确认。

**调参手段**：调试页显示当前值、采样间隔、失重段最低加速度、冲击峰值、阶段和阶段耗时；瞬态值保留到本次候选过程结束或人工清除。串口可输出有界长度的数据记录，不能靠 100 ms 刷新的瞬时读数还原 80 ms 波形。

### 5.3 JQ8900 一线串口语音

**唯一协议依据**：[JQ8900语音模块16p.pdf](JQ8900语音模块16p.pdf)，一线协议在第 7～11 页。PB0 接模块 **VPP**（第 4 页引脚表），不是 RX；RX/TX 属于另一套两线 UART 协议。

手册明确：按字节 **LSB 先发**，0 的高:低为 1:3，1 的高:低为 3:1；第 11 页说明脉宽比例基数 2～5 可识别。不得将 500/210 直接写成精确的 3:1。

**手册图与示例须分别看待**：

| 项目 | 手册依据 | 本项目处理 |
|---|---|---|
| 空闲与字节开始 | 第 10 页先置高并延时 1000 µs；字节结束回高 | 保持空闲高，开始高电平参考 1 ms |
| 引导低电平 | 第 7 页图与第 11 页要求 **大于 2 ms**；第 10 页代码用 2200 µs，第 11 页建议 4 ms | 按建议用 4 ms；不写成“≥2 ms” |
| 数据位波形图 | 第 7 页图标注长/短脉宽 >1200/>400 µs | 与第 10 页代码的绝对脉宽不一致，须用示波器核对，不能混成一套硬性时序 |
| 数据位示例代码 | 第 10 页：1=高 500/低 210 µs；0=高 210/低 500 µs | 作为手册给出的待测示例，不宣称满足第 7 页所有绝对脉宽标注 |
| 字节间隔 | 第 11 页建议 10 ms 以上 | 空闲高电平等待，并让出主循环；“10 ms”仅用于下述耗时估算 |

若沿用示例的 500/210 µs 并将引导低电平改成建议的 4 ms，单字节约 `1 + 4 + 8 × 0.710 = 10.68 ms`；三字节选曲加两个 10 ms 间隔约 **52 ms**。若按第 7 页较长数据脉宽发送，总时长还会增加。这些是波形总时长，**不是应关闭全局中断的时长**。

第 10 页 C51 代码关闭 EA，第 11 页建议关闭相关中断以减少波形扰动；不能据此把 STM32 的 UART/SysTick 整字节禁用。C07 先测量保留 UART/SysTick 时的实际高低脉宽及识别结果，若软件短延时不能同时满足时序和任务响应，使用定时器中断推进 PB0 GPIO 边沿；仅在中断中切换电平、记录下一边沿。具体定时器配置在 C07 明确后通过 CubeMX 生成，不占用新的外部引脚、不用 DMA。引导和字节间隔也应让出主循环。语音命令发送可以与 AT 响应/URC 接收并行，不以丢数据为代价。

**选曲指令**（第 8～9 页）：先清空数字 `0x0A`，再按十进制高位到低位发送 `0x00～0x09`，最后 `0x0B` 确认。例如第 2 首为 `0x0A,0x02,0x0B`，第 15 首为 `0x0A,0x01,0x05,0x0B`。手册用语是“最好先清空”；本项目固定先清空，避免上次数字残留。每个字节本身仍按 LSB 优先发送。

| 指令 | 功能 | 指令 | 功能 |
|---|---|---|---|
| `0x0A` | 清空数字 | `0x13` | 停止 |
| `0x0B` | 数字选曲确认 | `0x14/0x15` | 上一曲/下一曲 |
| `0x0C` | 数字设置音量 | `0x16/0x17` | 上一目录/下一目录 |
| `0x0D` | 数字设置 EQ | `0x18/0x19/0x1A` | SD/U盘/FLASH |
| `0x0E` | 数字设置循环模式 | `0x1B` | 系统睡眠 |
| `0x11/0x12` | 播放/暂停 | | |

文件放 FLASH 根目录，按第 9 页要求用五位数字文件名：`00001.mp3` 检测到跌倒、`00002.mp3` 已取消报警、`00003.mp3` 开机提示。不套用两线组合播放的 ZH 目录规则。持续报警还需明确循环/停止命令流程并实测，不能仅发送一次选曲就假定会一直播放。

BUSY 按第 4 页定义为有音频输出高、无输出低，PB1 可选接入；使用前核对实物输出。保持一线控制约束，不提供改成 IO 触发或两线 UART 的默认退路。

### 5.4 ESP-01S 网络（1471 号固件，AT 指令状态机）

**已确认事实**：ESP-01S 已刷入 **1471 号固件**。本项目以 [ESP-AT User Guide.pdf](ESP-AT%20User%20Guide.pdf) 为指令依据，不由“1471”推导 AT/SDK 版本、Flash 分区或缺省 UART 引脚，也不要求重新刷固件。

C08 首先经现有接线记录 `AT` 与 `AT+GMR` 的原始响应，然后验证 WiFi、SNTP 和本节 MQTT 指令。若实物响应与 PDF 不同，记录差异再核对该固件，不能擅自删除 `LinkID`、更换固件或改引脚；这是能力验证，不是重新讨论固件选型。

用非阻塞状态机串行发送命令，每条实际发送文本以 CR-LF 结束；上一条未结束前不下发下一条。以下为手册语法的项目参数示例，`ssid/pwd/broker` 是待填写参数：

| 步骤 | 指令 | 完成条件/注意 |
|---|---|---|
| 探测 | `AT`、`AT+GMR`（分两条） | `OK`，保存版本信息 |
| 关闭回显 | `ATE0` | `OK` |
| STA 模式 | `AT+CWMODE=1` | `OK` |
| 连 WiFi | `AT+CWJAP="ssid","pwd"` | 等最终 `OK/ERROR`；另行处理 `WIFI CONNECTED/WIFI GOT IP` |
| 查 IP | `AT+CIPSTA?` | `+CIPSTA:ip:"..."` 等字段及最终 `OK` |
| SNTP 配置 | `AT+CIPSNTPCFG=1,8,"cn.ntp.org.cn"` | `OK` 仅表示配置完成，不表示已获得有效时间 |
| 读时间 | `AT+CIPSNTPTIME?` | `+CIPSNTPTIME:<asctime style time>` 与 `OK`；检查时间有效性 |
| MQTT 用户配置 | `AT+MQTTUSERCFG=0,1,"belt01","","",0,0,""` | `OK`；需要鉴权时填写用户名密码 |
| MQTT 连接参数 | `AT+MQTTCONNCFG=0,120,0,"","",0,0` | `OK` |
| MQTT 连接 | `AT+MQTTCONN=0,"broker",1883,0` | 处理连接 URC 与最终结果；末参数 0 表示由 STM32 状态机管理重连 |
| 订阅 | `AT+MQTTSUB=0,"belt/belt01/cmd",0` | `OK` 或手册定义的已订阅响应 |
| 发布字符串 | `AT+MQTTPUB=0,"belt/belt01/loc","<转义后的JSON>",0,0` | `OK`；占位文本不能照发 |
| 断开并清理 | `AT+MQTTCLEAN=0` | `OK`；仅在需要清理会话时使用 |

MQTT 参数对应手册第 204～213 页（印刷页 200～209）：`LinkID` 当前仅为 0，`scheme=1` 是 TCP；`CONNCFG` 第三个参数 0 表示启用 clean session。本项目按 `USERCFG → CONNCFG → CONN → SUB` 配置；不要将项目选择的 CONNCFG 步骤误写成协议永远不能省略的必选步骤。重连成功后重新确认连接和订阅状态。

启动/恢复可通过 EN 拉低 100 ms 再拉高，并等待固件就绪；连续超时 3 次时可进入这条恢复路径。等待必须让出本地任务。SNTP 失败不得永久阻塞 MQTT；超时值在 C08 根据 1471 固件响应实测确定。

**接收帧**（第 212、216 页）：

```text
+MQTTSUBRECV:0,"belt/belt01/cmd",13,{"cmd":"loc"}
+MQTTCONNECTED:0,1,"broker",1883,"",0
+MQTTDISCONNECTED:0
```

`{"cmd":"loc"}` 是 13 个 ASCII 字节。SUBRECV 的数据按声明长度截取，不把 JSON 内部或后续 CR-LF 当作载荷结束；UART 一次接收与一条 URC 也没有一一对应关系。完整载荷复制到有界缓冲区并补 NUL，再交 App 解析。普通 AT 应答和 URC 可以交错到达，应分别识别。

**上行转义与长度**：

- `app_json` 只生成原始 JSON，AT 参数转义由 `bsp_esp` 处理。按手册第 244 页（印刷页 240），字符串内容中的反斜杠、逗号和双引号分别编码为 `\\`、`\,`、`\"`；参数分隔逗号及参数外层引号不转义。
- 以下只演示转义，不是完整业务报文。原始 JSON 为 `{"id":"belt01","fix":0}`，串口实际文本为：

```text
AT+MQTTPUB=0,"topic","{\"id\":\"belt01\"\,\"fix\":0}",0,0
```

对应 C 字符串需再经过 C 语言自身的一层转义：

```c
"AT+MQTTPUB=0,\"topic\",\"{\\\"id\\\":\\\"belt01\\\"\\,\\\"fix\\\":0}\",0,0\r\n"
```

- 手册第 244 页的 `sensor:012` 特殊字符示例不宜直接当成合法 JSON 模板；项目按字段生成合法 JSON，并在订阅端验证收到的原始字节。
- `AT+MQTTPUB` 的 **整条 AT 命令**受 256 B 限制，topic 最长 128 B；检查转义膨胀后的命令长度，发送缓冲区还需容纳 CR-LF 和 NUL，不把它解释为“单独可发 256 B JSON”。
- 手册第 210～211 页的 `AT+MQTTPUBRAW=0,"topic",<length>,0,0` 是另一种发送方式：等 `OK` 和 `>` 后发送恰好 length 个原始载荷字节，不做 AT 转义、不附加 CR-LF；再等 `+MQTTPUB:OK/FAIL`。ESP8266 的默认 512 B MQTT 缓冲包含 MQTT 头和 topic 开销，不能视为 512 B 可用 JSON。是否采用 RAW 在 C09 实现时确定。

### 5.5 时间同步

联网后配置 SNTP，再轮询到有效时间，通过 BSP 写入 STM32 RTC；此后 RTC 由 LSE 独立走时。SNTP 配置成功不等于同步成功；返回未同步时间、无效日期或超时不能置“已校准”。SNTP 超时可继续建立 MQTT，界面仍标注“时间未校准”，联网后安排有限频率的校时重试。

`AT+CIPSNTPTIME?` 见手册第 114～116 页（印刷页 110～112），返回 `Www Mmm dd hh:mm:ss yyyy`，例如 `Sat Oct 24 21:30:00 2026`。解析英文月份和日期，兼容个位日期的空格填充。按 `CIPSNTPCFG=1,8,...` 得到的本地时间写入 RTC，不能再加一次 8 小时。

上报 `ts` 定义为 **Unix UTC 秒**：RTC 保存东八区日历时，将本地日历转换为 UTC（减去 8 小时，处理跨日）再计算距 1970-01-01 00:00:00 UTC 的秒数。不能直接把 F1 的 RTC 计数寄存器当成 Unix 时间。未完成有效校时则 `ts=0`，服务器不得把它解释为真实事件时间。持续时间判断全部使用 tick，不受校时跳变影响。

### 5.6 JSON 处理

**上行**：在固定大小缓冲区内用 `snprintf` 拼装并检查返回长度，避免引入 cJSON 的 malloc。
经纬度用**整数微度**（`lat × 10⁶`）传输，即 `"lat":22615755`，这样完全不用浮点 `printf`，省掉 `-u _printf_float` 带来的几 KB 开销，不代表 GPS 测量或度数转微度过程没有误差。

**下行**：只支持下面的固定命令集合，不引第三方库。在 AT 层确认完整载荷后，用 `strstr` 定位键并校验冒号、字符串边界及数值结束位置；拒绝截断载荷、缺失参数、无效数字和超出 C09 确认范围的周期。不能把“找到了子串”当作任意 JSON 的完整解析。解析后交给系统状态机执行。

```text
/* 上行：周期位置状态  topic: belt/belt01/loc */
{"id":"belt01","ts":1761288000,"lat":22615755,"lon":114141317,"fix":1,"sat":8,"st":"ok"}

/* 上行：跌倒报警    topic: belt/belt01/alarm */
{"id":"belt01","ts":1761288000,"ev":"fall","lat":22615755,"lon":114141317,"fix":1,"sat":8}

/* 上行：取消报警    topic: belt/belt01/alarm */
{"id":"belt01","ts":1761288000,"ev":"cancel"}

/* 下行：服务器命令  topic: belt/belt01/cmd */
{"cmd":"loc"}          /* 立即上报一次位置 */
{"cmd":"clear"}        /* 清除报警状态 */
{"cmd":"intv","v":30}  /* 修改上报周期为 30 s */
```

以上代码块的注释只用于解释 topic，每次实际载荷只有一个 JSON 对象，不带注释。字段名、topic 和命令名保持不变。

字段说明：`ts` 为 Unix UTC 秒、未校时为 0；`fix` 为归一化的有效定位标志 0/1，含过期判断；`sat` 为最近定位数据中的参与定位卫星数；`st` 为 `ok` / `fall`。从未定位时坐标为 0 且 fix=0，有历史有效位置时失锁沿用该坐标。

### 8.1 后端 / 演示端范围

需求文档提到"后端与嵌入式之间用 MQTT 通信"，但器材清单全是嵌入式器件，所以**后端只做演示级**，不写正式服务：

- 一个 MQTT Broker（公共测试服务器，或本机 Mosquitto/EMQX）。
- `Tools/server.py`：Python + `paho-mqtt`，订阅 `belt/belt01/#`，把收到的 JSON 格式化打印到控制台（跌倒时高亮），并支持从键盘发下行命令。演示时它就是"后端"。
- 若课程要求有可视化界面，可在此基础上加一个简易网页地图打点，但**不属于固件开发范围**，排期上不占 C01~C10。

### 10.1 风险与验证

| # | 风险 | 影响 | 应对 |

| 1 | 已刷入的 1471 号固件尚无本项目实测版本响应/能力记录 | 指令与实物不匹配 | C08 经现有串口记录 AT+GMR，验证 PDF 的 WiFi/SNTP/MQTT 指令；不推断 NonOS 语法、不自行重刷 |
| 2 | 跌倒阶段③时限与静止判据未定 | 无法据此实现正式判定 | 用户要求保留待确认，C06 标定后确认，不能提前选择两个 3 s 窗口 |

| 8 | 室内或遮挡条件下 GPS 无定位/定位过期 | 演示无有效位置 | 尽量在开阔环境提前上电；显示未定位，按 fix 标记无效坐标；首次定位时间随环境变化 |
| 9 | 经验阈值、量程与安装方向未标定 | 跌倒误报/漏报、冲击轴饱和 | C04/C06 用正常活动与受控装置运动数据标定，记录原始数据和量程；不要求佩戴者做危险摔倒 |

### 10.2 创新性设计小结

1. 三段式时序判据尝试区分躺下与跌倒，以标定后的误报/漏报结果验收
2. 10 s 按键撤销窗口，兼顾"立即报警"与"减少误报"
3. 下行 MQTT 命令，支持远程查询位置、消警、改上报周期
4. 经纬度用整数微度传输，避免浮点 printf，节省 Flash
5. 失锁时沿用上次有效坐标并置 `fix=0`；从未定位时的零坐标也必须由 fix 标记无效
6. OLED 三页界面 + 报警自动跳页 + 状态栏图标，另加一页算法调试页实时显示跌倒判据数据

### 10.3 待确认与验收事项

1. 引脚按第 3 章与 AGENTS.md 固定，不重新分配；实际接线与表不一致时先反馈。
2. **阶段③入口期限、持续静止时长、静止判据与复位规则：用户要求留待 C06 标定确认。** 现有 0.6 g / 80 ms / 2.0 g / 1.5 s / 60° / 0.7～1.3 g 为候选参数，变化前先确认。
3. MQTT broker 的地址、端口、鉴权；上报周期允许范围、离线 fall/cancel 是否补报及顺序，C09 前确认。
4. K1 翻页、K2 消警/测试的键位交互在 C02 验证。
5. C07 根据 JQ 手册测定脉宽和模块识别情况，验收 UART 接收与 IMU 调度并发；BUSY 按手册高有效并核对实物。
